Fragment (Standard)

Introduction

Wicket is very flexible when it comes to fragments, and supports most combinations of the table below (and more). But the DSL only supports the combinations specifying which Fragment classes can be used. Explanation of the table headers and cell values:

Markup Location

Own markup
The fragment has its own markup file.
Markup in parent
The fragment markup is embedded in the parent markup to which the fragment is added.
Markup in other component, also supplying components
The fragment markup is embedded in the markup of a descendent component. The descendent component also creates the descendent components of the fragment. However, the adding of the components to the fragment is still done by the parent.
Markup in other component, not supplying components
The fragment markup is embedded in the markup of a descendent component. The fragment does not contain descendent components.

Components Location

No components
The fragment does not contain components.
Own components
The fragment creates its descendent components itself.
Components in parent
The parent of the fragment creates the descendent components of the fragment. The adding of the components to the fragment is done by the parent.
Components in other component, also supplying markup.
A descendent component creates the descendent components of the fragment. However, the adding of the components to the fragment is still done by the parent. The descendent component also supplies the fragment markup.
Components in other component, not supplying markup
A descendent component creates the descendent components of the fragment. The fragment markup is located somewhere else than embedded in the descendent component markup.

Allowed Fragment Classes

-
This combination is not supported by the DSL.
(Un)specialized
Fragment can be used as is. A subclass is also allowed.
Specialized only
A subclass of Fragment must be used.

Note that the (subclass of) Fragment is always added directly to the page in the examples below.

In all cases multiple fragment markup variants are supported. A random one is chosen in each example when the page is loaded and refreshed.
